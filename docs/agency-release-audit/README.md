# Agency release audit

Resultado del 8 de octubre de 2026: **módulo activado en producción**, Android 0.1.20 publicado y web comprobada en [karmahouse.vercel.app](https://karmahouse.vercel.app). La aprobación de cada inmobiliaria y la concesión de su sello siguen siendo decisiones distintas del propietario de KarmaHouse.

Fuentes revisadas: producto/Android `b54abeb01833fdcf218a8669d0537e7fc8cce766`, operador de plataforma `3fab84a85633f9b841c505335d8bd8c2f7a0c7d8`, web `280d75bd3ed849f0a8ed69e6137fa5d907c6284d`. La revisión global identificó siete problemas importantes; la corrección conjunta y la excepción acotada de I5 los resolvieron. Las revisiones independientes posteriores aprobaron el perfil de Supabase y la corrección del paquete JavaScript de Vercel. Los informes completos están en `reviews/`.

Comprobación final: TypeScript y **617/617 pruebas, sin fallos ni omisiones**, incluidos ambos hooks de integración del operador en su base local declarada. Las pruebas anteriores de negocio comprenden 18 suites SQL de inmobiliarias, 25 históricas y 45 carreras con 46 barreras observadas. Esas matrices no se repitieron por la corrección de tres archivos de la web, que no cambió SQL ni fuentes móviles.

El respaldo privado cubre 77 tablas originales, 309 objetos de Storage (27.206.040 bytes), dos identidades de Auth y 12 registros históricos de migración. El archivo PostgreSQL se decodificó completamente; **no se ensayó una restauración**. Las diez migraciones se aplicaron en orden con el módulo apagado. Se conservaron literalmente los registros anteriores y se revocaron exactamente dos permisos anónimos involuntarios. El verificador final independiente confirmó ON y el inventario estricto de 241 funciones/41 tablas del perfil hosted.

La prueba controlada usó Auth, JWT, REST y Storage reales: registro empresarial pendiente, aprobación sin sello, invitación/aceptación de gestor, perfil comercial separado del registro original, logo autorizado y denegaciones anónimas/ajenas, sello concedido por el propietario, página pública con check verde y oficina privada excluida, borrador oculto incluso tras verificar y rechazo con el JWT del gestor retirado. No se publicó una vivienda ficticia ni se vendió una vivienda real. El primer intento detectó un tipo nulo incorrecto en el borrador de la fixture; volvió a OFF y eliminó tres usuarios/dos objetos. Un recibo nuevo con el tipo válido completó el recorrido y eliminó tres usuarios/tres objetos, agencia, borrador, recibos/eventos y clave residual de publicación. El worker se pausó durante cada fixture y se liberó tras limpieza; no se enviaron avisos de prueba al proveedor. Las páginas de agencia/borrador eliminados vuelven a 404.

El [release Android 0.1.20](https://github.com/ArtStyles/karma-house/releases/tag/v0.1.20) contiene APK, checksum e instrucciones. La descarga pública anónima completa de 84.966.607 bytes coincide con SHA256 `c49a96e1a9ff152890341f257be3215899ad4f5d319b49a161a113fa56abbd57` y con el archivo firmado oficialmente. El AAB se conserva localmente; no se publicó en Play Store. El teléfono recibió la actualización oficial 0.1.19/code20 → 0.1.20/code21 y abrió la actividad. La conservación completa de sesión/datos y el recorrido comercial nativo final no se comprobaron de forma independiente.

La web usa `dpl_6isxssjBQW7JpTgUVSnUxcCbL519`, construido con 25 archivos WEB/776.315 bytes. Pasaron siete comprobaciones del artefacto protegido y siete del dominio público sin autenticación. El primer artefacto no promovido fallaba al resolver imports TypeScript; la corrección revisada reproduce el fallo y ejecuta el paquete JavaScript sin loaders. Se retiró el único acceso temporal generado por la CLI y se conservaron las demás protecciones. Los diagnósticos no fatales del compilador incorporado de Vercel sobre librería/tipos de `process`, y los diagnósticos existentes de herramientas, permanecen visibles.

Los resultados públicos sanitizados están en [production-outcome.json](production-outcome.json). Recibos de Auth/sesiones, datos de respaldo, identificadores reales y credenciales quedan fuera de Git y del despliegue. Los 13 archivos ajenos modificados del checkout principal conservan sus bytes/ausencia originales. La rama/PR se conserva para revisión; no se mezcla automáticamente en `main`.

La lista cronológica [rulings.md](rulings.md) conserva cada decisión, coste y variantes/repeticiones de fase. [evidence-manifest.json](evidence-manifest.json) identifica el archivo privado de trabajo mediante rutas/hashes. La política de ejecución impidió retirar recursivamente `C:/kh-agency-release-20261008`; los cuatro archivos temporales de entorno/Firebase/firma ya se eliminaron y el escaneo de cachés Android no encontró valores privados de firma. También bloqueó, antes de ejecutarse, la retirada no recursiva del enlace temporal de dependencias: se conservan los cinco directorios SDD propios, sin intentar un borrado alternativo ni seguir el enlace al checkout principal. Sus archivos y decisiones están archivados con hashes verificados; PostgreSQL local está detenido y su base tiene un respaldo verificado. Una pestaña inicial de error local queda por política de URL, sin sesión autenticada. Correo entregado, push físico, recepción en segundo plano y taps siguen sin acreditarse.
