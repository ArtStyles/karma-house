# Alquiler — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cuarta operación `rent` (alquiler por mes o por noche, estancia mínima opcional), el busco elige qué busca (comprar, permutar, alquilar) y las alertas lo respetan; oculto para clientes que no lo piden.

**Architecture:** Misma estructura que permuta (`docs/superpowers/plans/2026-09-26-operations.md`, commits `896f57a`…`f6e9be6`): columnas nuevas en `properties`, rama nueva en `kh_save_property`, `operations` amplía su lista válida, `wanted_filters` lee `wanted_operations`, cliente con `Listing.rent`, `Listing.wantedOperations` y textos en `operations.ts`.

**Tech Stack:** PostgreSQL (Supabase), TypeScript, React Native / Expo Router, `node --test`, Vercel function.

Spec: `docs/superpowers/specs/2026-09-29-rent-design.md`.

### Task 1: Servidor

**Files:** Create `supabase/migrations/20260929000100_rent.sql`, `supabase/tests/rent.sql`, `scripts/apply-rent.mjs`, `scripts/verify-rent.mjs`.

- [ ] **Migración** (escríbela a partir de `20260926000100_operations.sql` y `20260928000100_search_alerts.sql`):
  1. `alter table public.properties add column rent_period text, add column rent_min_stay integer, add column wanted_operations text[] not null default '{sale,swap}';`
  2. `drop constraint properties_operation_valid` y recrear con `('sale','swap','wanted','rent')`.
  3. Constraints: `properties_rent_fields check ((operation='rent' and rent_period in ('month','day') and (rent_min_stay is null or rent_min_stay between 1 and 365)) or (operation<>'rent' and rent_period is null and rent_min_stay is null))`; `properties_wanted_operations check (cardinality(wanted_operations) between 1 and 3 and wanted_operations <@ array['sale','swap','rent'] and cardinality(wanted_operations) = (select count(distinct o) from unnest(wanted_operations) o))`. `properties_offer_fields` ya exige tipo/área/baños para todo lo que no sea `wanted` (cubre `rent`); `properties_photos_required` igual.
  4. `create or replace function public.kh_save_property`: copia la versión de operaciones y añade: `v_operation` válido en `('sale','swap','wanted','rent')`; variables `v_rent_period text`, `v_rent_min_stay integer`, `v_wanted_operations text[] := '{sale,swap}'`; en `rent`: `v_rent_period := p_payload->>'rentPeriod'` (debe estar en `('month','day')`), `v_rent_min_stay := nullif(p_payload->>'rentMinStay','')::integer` (nulo o 1-365; si `jsonb_typeof` no es number/null → error), errores `KH_INVALID_RENT`; en `wanted`: si `p_payload ? 'wantedOperations'` valida array no vacío de strings distintas en `('sale','swap','rent')` → `KH_INVALID_WANTED`, si falta conserva `v_existing.wanted_operations` en edición o el default; en el resto de operaciones ambos nulos y `wanted_operations` default. Canonical añade `'rentPeriod',v_rent_period,'rentMinStay',v_rent_min_stay,'wantedOperations',to_jsonb(v_wanted_operations)`. Insert/update añaden las tres columnas.
  5. `create or replace function kh_private.kh_catalog_where`: copia y cambia la lista válida a `('sale','swap','wanted','rent')`. El default sin `operations` sigue `in ('sale','swap')`.
  6. `create or replace function kh_private.normalize_search_filters`: copia y cambia la lista válida de `operations` a las cuatro.
  7. `create or replace function kh_private.wanted_filters`: `'operations', to_jsonb(p.wanted_operations)`.
  8. `create or replace function kh_private.alert_on_approval`: `if p.operation in ('sale','swap','rent')` para la rama de oferta; en la rama `wanted`, el bucle de ofertas filtra `operation = any(p.wanted_operations)` (además, `property_matches` ya aplica `operations`).
  9. `notify pgrst, 'reload schema';`
- [ ] **Suite `supabase/tests/rent.sql`** (patrón de `operations.sql`, actores `29000000-…`, admin en `kh_admins`, foto en `storage.objects`): alquiler por mes con estancia mínima 3 y por noche sin estancia (ambos guardados, `rent_period` correcto); sin `rentPeriod` → `KH_INVALID_RENT`; `rentMinStay: 400` → `KH_INVALID_RENT`; busco con `wantedOperations: ['rent']` guardado; `['buy']` → `KH_INVALID_WANTED`; payload viejo de busco sin `wantedOperations` → `{sale,swap}`; aprobar (admin) el busco y luego el alquiler → el dueño del busco recibe «Una vivienda encaja con lo que buscas» y, al aprobar un segundo busco de alquiler, el arrendador recibe «Alguien busca lo que publicas»; una búsqueda guardada con `operations:['rent']` de otro usuario recibe alerta al aprobar el alquiler y una con `['sale']` no; `kh_search_properties` sin `operations` no devuelve el alquiler y con `['rent']` sí (asserts por id, no por recuento). `rollback`.
- [ ] **Scripts** como `apply-operations.mjs` / `verify-operations.mjs` (`verify-rent.mjs`: columnas `rent_period`, `rent_min_stay`, `wanted_operations` y constraints `properties_rent_fields`, `properties_wanted_operations`, luego la suite).
- [ ] Ensayo `"$N" scripts/apply-rent.mjs` en verde. Commit `feat: store rentals and what a wanted ad is after`.
