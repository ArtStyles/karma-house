# Fichas públicas

El dominio oficial es `karmahouse.site`, comprado en GoDaddy y conectado al proyecto existente de Vercel. Vercel redirige la raíz a `https://www.karmahouse.site/`, dirección final usada en los metadatos, enlaces de descarga y enlaces compartidos de la app. La app acepta ambas variantes del dominio y los enlaces anteriores de `karmahouse.vercel.app`; las fichas servidas desde ese alias indican la dirección oficial como URL canónica. Los documentos legales conservan sus direcciones de GitHub Pages.

Proyecto Vercel con Root Directory `web`. `api/p.ts` sirve `/p/<id>` (reescrito en `vercel.json`) con la página pública de un anuncio aprobado y activo; el HTML se genera en el mismo archivo, sin imports, para que Vercel no tenga que resolver extensiones `.ts`; lo prueban `tests/public-listing.test.ts` desde la raíz del repo.

Variables de entorno del proyecto: `SUPABASE_URL` y `SUPABASE_ANON_KEY` (los mismos valores públicos de `.env.local`). La portada es una app de Vite + React + Tailwind CSS 4 con `motion` (antes Framer Motion) para animaciones: `index.html` lleva las metaetiquetas, `src/App.tsx` el contenido y `src/style.css` los estilos propios, que se cargan después de Tailwind. `public/` solo guarda imágenes y `robots.txt`, que Vite copia a `dist/`. Vercel ejecuta `npm run build` y publica `dist/` (fijado en `vercel.json`). En local: `npm install` y `npm run dev` dentro de `web/`. El alias `@/` apunta a `src/`, como esperan los componentes de 21st.dev y shadcn. `.vercelignore` excluye `tsconfig.json` para que la compilación de `api/p.ts` en Vercel no cambie; no instalar `typescript` en `web/` por el mismo motivo. La portada no consulta el catálogo ni muestra anuncios o cifras de actividad inventadas. Las fotografías y la conversación de ejemplo están identificadas como ilustrativas.

La portada está preparada para KarmaHouse 0.1.20 y la futura release `v0.1.20`; esta preparación local no acredita su publicación. El botón principal lleva al bloque de descarga con APK, instrucciones y SHA-256 de la misma versión. Se omite el tamaño hasta tener un artefacto real. No publicar estos enlaces hasta comprobar la release nueva mediante descarga anónima completa y hash. La página no incorpora aún el observatorio inmobiliario propuesto.

El despliegue CLI parte de la raíz del repositorio, dirigido al proyecto existente con Root Directory `web`. La `.vercelignore` de la raíz permite exclusivamente `web`, conserva la exclusión de `web/tsconfig.json` y excluye dependencias, resultados y entorno local. Ejecutar `vercel deploy --dry` y revisar su inventario antes de subir; no ejecutar desde `web` contra un proyecto que ya agrega esa Root Directory. La release empresarial incluye también el handler de fichas públicas `api/p.ts`, no solo los enlaces de la portada. Procedimiento, destino y reversión: [release de inmobiliarias](../docs/agency-workspaces-release-runbook.md).

El rediseño de octubre de 2026 toma como referencias la organización por intención de Idealista, Rightmove y Zillow, manteniendo una portada de presentación porque el catálogo se usa en la app. Conserva las rutas `/p/<id>` y los enlaces legales.

La portada es una narrativa de scroll (spec: `docs/superpowers/specs/2026-10-11-web-scroll-narrative-design.md`). Cada escena de `src/scenes/` es una pista alta (`.track`) con un escenario fijo (`.stage`); `src/motion.ts` da el avance con `useScroll` de `motion` y cada escena escribe estilos en sus elementos `data-part` sin volver a renderizar. Las escenas solo se fijan con JavaScript (el `<head>` añade `.js`) y sin movimiento reducido; si no, todo se lee como contenido estático. `useMode` elige `full`, `lite` (ahorro de datos o poca memoria: sin luz, grano ni balanceo) o `static`. Textos y hechos están en `src/content.ts`; la matemática pura en `src/scroll.ts`, y ambos tienen pruebas en `tests/web-*.test.ts` (`node --experimental-strip-types --test tests/web-*.test.ts` desde la raíz). El teléfono (`src/phone/`) imita la app con datos ilustrativos. El mapa de Cuba (`src/cuba-map.ts`) se genera con `node web/scripts/cuba-map.mjs <geojson>` desde geoBoundaries (OpenStreetMap, ODbL) y se carga solo al acercarse. Las provincias copian `PROVINCES` de `src/domain/listingOptions.ts` y una prueba lo comprueba. `public/404.html`, `sitemap.xml` y `robots.txt` completan el SEO; el JSON-LD (`FAQPage` y `MobileApplication`) sale de `content.ts` durante el prerender.
